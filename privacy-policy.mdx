### 4.4. Telegram integration data

When using features that require integration with Telegram, the Service may process:

1. texts of messages from chats and channels to which the user has explicitly requested access;
2. message metadata (date, author, identifiers);
3. links and identifiers of chats and channels;
4. the user’s Telegram session (StringSession), which is stored in encrypted form using the Fernet algorithm (AES-128);
5. the Telegram two-factor authentication password (2FA password) — processed in transit only, exclusively at the moment of authorization, and never stored in the Service database (see section 11 “Data security”, subsection on protection of the 2FA password).

**Access limitation (Scope).** The Service obtains access only to data explicitly specified by the user. CoTel:

1. does not perform background or unauthorized data collection;
2. does not access chats and channels without the user’s explicit request;
3. does not have unrestricted access to the user’s Telegram account;
4. does not store the full archive of correspondence.

### 4.5. Service Telegram accounts

2. are used exclusively to perform the functions of the Service;
3. are not provided to users for management.

When service accounts are used, the user’s request and the received content pass through the Service infrastructure and AI providers under the same conditions as when the user’s personal Telegram account is used.

## 11. Data security

We apply technical and organizational security measures aimed at protecting personal data from unauthorized access, alteration, disclosure, or destruction. These include:

1. data transmission over a secure HTTPS / TLS connection;
2. storage of user passwords only as cryptographic hashes (bcrypt algorithm);
3. encryption of users’ Telegram sessions using the Fernet algorithm (AES-128);
4. additional encryption of the Telegram 2FA password during transmission — on top of HTTPS (described in detail below);
5. protection of cookies with HttpOnly and Secure attributes;
6. email verification during registration;
7. the principle of least privilege for personnel access to data;
8. exclusion of sensitive data from logs and journals;
9. regular database backups.

### 11.1. Additional protection of the Telegram 2FA password

If the user has two-factor authentication (2FA) enabled in Telegram, the Service requires a one-time entry of the corresponding 2FA password for authorization. The Service applies an additional layer of encryption to this password on top of the standard HTTPS connection:

1. The server generates a one-time asymmetric RSA key pair with a length of 2048 bits and the OAEP padding scheme (SHA-256).
2. The public key is transmitted to the user’s browser; the 2FA password is encrypted with this public key directly on the user’s device before being sent to the server.
3. The received 2FA password is decrypted with the private key exclusively in the server’s RAM, used once for authorization in Telegram, and immediately deleted.
4. The corresponding private key exists only in the server’s RAM, is not written to disk, and is not stored in the database. The validity period of the cryptographic context is no more than 5 minutes; after this period expires, the context is automatically destroyed.
5. The Telegram 2FA password is never stored in the database, is not written to logs, and is not transferred to any third parties except Telegram itself (through its official API).

This measure provides additional protection even in the event of compromise of the transmission channel or unauthorized access to server logs.

Despite the measures taken, no system can guarantee absolute security. The user must observe their own security measures, including using a strong password and not sharing access to the account with third parties.
