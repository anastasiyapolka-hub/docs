**Event** subscriptions help you avoid missing important messages in Telegram chats and channels. You define a condition: what exactly to look for, where to look, and how often to check new messages. When CoTel finds matching messages, it sends you a Telegram notification.

This subscription type is useful when you do not want to read the whole chat manually and only need a signal when something specific appears: a listing, job opening, discount, error, recommendation, product mention, or important event.

<Info>
  An Event subscription works best when the query is specific: what to look for, which words or meanings to consider, which parameters matter, and what can be ignored.
</Info>

## How each example is structured

Each scenario below shows:

- **Subscription name** — how you can name it in CoTel
- **Subscription type** — Events
- **Where to use it** — the suitable type of chat or channel
- **Frequency** — a reasonable check interval
- **Example query** — what to write in the query field
- **What you will receive** — what kind of result you will get in Telegram

## How to write good conditions for Event subscriptions

A good Event subscription usually includes:

1. **What to look for** — product, job, problem, topic, event, or mention
2. **Where to look** — a specific chat, channel, or group
3. **Which parameters matter** — price, district, model, work format, age, country, date
4. **What to ignore** — irrelevant options, if important
5. **How often to check** — the more urgent the task, the more frequent the check can be, if your plan allows it

<AccordionGroup>
  <Accordion title="Too broad request">
    “Notify me about apartments.”

    This request may produce too many irrelevant matches.
  </Accordion>

  <Accordion title="More effective request">
    “Notify me when there are apartment rental listings in Vake or Vera. I am interested in 1–2 bedrooms, decent renovation, preferably with parking.”

    This request specifies the district, object type, and important parameters, so CoTel can select messages more accurately.
  </Accordion>
</AccordionGroup>
